# Дизайн до реализации

Сервис принимает короткие задания с именем, длительностью имитации и признаком предсказуемой ошибки. HTTP-процесс и как минимум четыре независимых процесса worker используют один PostgreSQL. База даёт транзакции для результата и эффекта, блокировки строк и параллельный выбор свободной работы через `FOR UPDATE SKIP LOCKED`. Это также позволяет проверять протокол на тех же блокировках, которые будут в развертывании.

**Приём.** Уникальный ключ запроса хранится вместе с заданием весь срок его жизни. Сервер возвращает идентификатор только после фиксации записи. Повтор с теми же параметрами возвращает текущее состояние того же задания, смена параметров при том же ключе даёт 409. При конфликте вставки повторное чтение выполняется новым оператором в READ COMMITTED, чтобы увидеть победителя. Список использует возрастающий первичный ключ и курсор. Это обход живой очереди, без снимка между страницами.

**Захват и восстановление.** Один короткий оператор выбирает и блокирует доступную строку, переводит её в running, увеличивает номер попытки и выдаёт lease. Доступны queued и running с истёкшим lease. Worker освобождает транзакцию до начала имитации. Во время долгого задания он периодически продлевает lease. Все решения о сроке действия принимает один PostgreSQL по своим часам. Погибший процесс перестаёт продлевать lease, следующий захват увеличивает номер попытки. Пропавший ответ на фиксацию захвата также восстанавливается через истечение lease. Ошибка инфраструктуры оставляет возможность повтора, заданная параметром ошибка исполнения завершает задание в failed.

**Завершение и отмена.** Завершение и продление проверяют состояние, номер попытки и срок lease, удерживая блокировку конкретной строки. Проснувшийся старый worker теряет право писать. Завершение успешной попытки в одной транзакции меняет состояние и вставляет строку эффекта, ссылающуюся на задание и номер попытки. Уникальность job_id дополнительно защищает эффект. Отмена одной записью переводит queued или running в cancelled и очищает lease. При гонке побеждает первая зафиксированная смена состояния. Поздняя отмена видит терминальное состояние, позднее завершение теряет право на запись. Имитация может продолжаться локально до ближайшей проверки.

**Гарантия.** Попыток исполнения может быть несколько. Каждому зафиксированному succeeded соответствует ровно одна зафиксированная строка эффекта, failed и cancelled соответствуют нулю. Гарантия распространяется на эффект в этой БД при сохранности зафиксированных транзакций. Завершение очереди требует доступной БД и хотя бы одного worker, способного удержать lease до конца попытки. Для реального вызова внешнего тренера потребуется отдельный протокол идемпотентности у получателя.
